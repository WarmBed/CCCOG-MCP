## 1. Requirements and non-goals

### 1.1 Product goal

CCCOG-Bar is a resident Windows utility whose main view is a live control-flow
graph.  Nodes are provider sessions (`claude`, `claude-child`, `codex`,
`grok`); edges are dispatch or PATH A owner relationships.  Each edge shows a
bounded first-line task summary and status animation.  The bar also shows
integer token totals per node and edge, plus horizontal quota cards like a
Claude Code five-hour/weekly panel.

The graph/token inputs are read-only local files.  Quota cards may make only the
bounded calls in §2.4.  No prompt, transcript, cwd, job id, or other local file
content is ever sent to a provider.

### 1.2 Mandatory requirements

1. Incremental, bounded parsing and graph aggregation must keep the shell
   responsive and avoid rereading unchanged bytes.
2. Correlate dispatch status, prompt summaries, owner leases, audit history,
   and provider session usage into deterministic nodes and edges.
3. Keep prompt/audit text untrusted: first-line only, escaped, UTF-8 bounded,
   never executed or expanded as an instruction.
4. Parse per-message input/output/cache-read/cache-write token counts and
   attribute them once to nodes and applicable edges.
5. Preserve the additive `callerLabel` contract from Batch 1.  It is display
   metadata, not an authenticated identity; old jobs fall back to an explicit
   ambiguous hop source.
6. Add quota cards for Codex, Claude, and Grok with the source and failure rules
   in §2.4.  A quota failure must never block graph refresh or dispatch.

### 1.3 Operator decision: remove pricing

Cost calculation is **out of scope**.  Remove pricing/LiteLLM/OpenRouter,
pinned-rate tables, `costUsd`/`costMicroUsd`, and `costSource` from the
`UsageSample` DTO, implementation, tests, and UI.  The bar reports tokens and
quota percentages only; it never displays or derives money.

### 1.4 Non-goals

- No provider inference/messages API, billing transaction, quota enforcement,
  provider process launch, or dispatch behavior change.
- No full transcript/prompt display and no remote upload of local data.
- No simultaneous WinUI/egui/Tauri shells; the approved architecture remains a
  Rust core with a thin WinUI 3 shell.

## 2. Verified data contracts

### 2.1 CCCG files

The core reads these with shared-read semantics and tolerates a torn final
JSONL line.  `cccg-archive` descendants are excluded from every scan.

| Source | Fields used | Rule |
| --- | --- | --- |
| `%LOCALAPPDATA%\\CCCG\\dispatch\\jobs\\*\\status.json` | `jobId`, provider/session ids, cwd, model/effort, hop fields, `callerLabel`, action/status/error, timestamps | Unknown/old fields are optional; job id is the stable edge id. |
| `jobs\\*\\prompt.txt` | generated dispatch header plus prompt | Read a bounded prefix, strip header, take first task line, escape and truncate. |
| `owners\\*.json` plus lease | provider/session/cwd/owner pid/spool/timestamp | Lease/process liveness decides PATH A edge; stale JSON is diagnostic only. |
| `inbox.jsonl` | sender/recipient ids, content, job id, timestamp | Stream audit metadata; content remains inert untrusted data. |
| Provider sessions | Codex rollout JSONL, Claude project JSONL, Grok local session files | Provider adapter, cursor/mtime, stable message dedup; archive paths excluded. |

### 2.2 Token DTO and attribution

```text
UsageSample {
  provider, sessionId, messageKey, timestamp, model,
  inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens,
  sourcePath, sourceOffset
}
```

Token counts are integer values.  Missing usage is `None`/unknown, never a
fabricated zero.  No floating point money type, decimal crate, micro-USD field,
pricing table, or cost source is allowed in Batch 2.

Codex adapters parse rollout usage objects; Claude parses assistant
`message.usage` variants; Grok parses observed local usage fields and reports
unknown when absent.  The cursor is `(path identity, length, mtime, byte
offset)` plus a stable message hash.  Truncation/rewrites reset it.  Failed or
queued jobs do not receive unobserved usage.

Node usage is the deduplicated sum for a real `(provider, sessionId)`.  A job
edge receives target-session samples in its started/finished interval; samples
that cannot be bound to one edge stay once in the node total and are marked
unallocated.  PATH A usage is bounded by the live owner interval.  Requested
session to resolved session updates one edge, not two.

### 2.3 Graph DTO

```text
GraphSnapshot { generatedAt, sourceRevision, diagnostics[], truncated,
                nodes[], edges[], totals }
Node { id, provider, sessionId?, label, kind, state, usage }
Edge { id, kind, sourceNodeId, targetNodeId, jobId?, taskSummary,
       status, timestamps, usage, identityConfidence }
```

`dispatch` edges use `callerLabel` when present; old jobs use a namespaced
`hopSource/hopChain` node with `identityConfidence=ambiguous`.  `path_a_owner`
edges use live owner registrations.  Cycles are finite data with a diagnostic,
not recursive traversal.  Archived, malformed, stale, and missing records are
badges/diagnostics, never invented relationships.

### 2.4 Quota cards: approved read-only network exception

```text
QuotaCards {
  clientId,
  windows: [{ cardId, label, usedPercent, remainingPercent, resetsAt? }],
  state: fresh | stale | unavailable,
  observedAt?, diagnostic?
}
```

Percentages are clamped/validated to 0..100; `resetsAt` is optional and never
guessed.  The shell renders one horizontal bar per window and no dollar value.

- **Codex, local first:** read the latest rollout JSONL `rate_limits` object
  (`used_percent`, `window_minutes`, `resets_at`).  No Codex network call.
- **Claude:** only `GET https://api.anthropic.com/api/oauth/usage` using the
  read-only OAuth credential under `~/.claude`.  An expired token may use only
  `POST https://platform.claude.com/v1/oauth/token`; refresh credentials are
  never written back.  A 403 inference-only token becomes unavailable; never
  probe the Messages API.
- **Grok:** only `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`
  using the read-only credential in `~/.grok/auth.json`.  No credential means
  hide the Grok card and make no fallback call.

The HTTP client is injected.  Tests use synthetic 200/401/403/timeout/malformed
responses and never touch the network.  Background polling defaults to at
least 60 seconds and is configurable.  Failure keeps the last bounded value
with a stale/unavailable badge and never blocks graph refresh.  Requests carry
only endpoint, required headers, and token; no local CCCG/provider data.

## 3. Architecture and workspace

Keep the approved Rust core + thin WinUI 3 shell.  Rust owns file parsing,
token usage, graph reduction, quota normalization, and the injected HTTP
client.  WinUI owns tray/window/flyout, graph rendering, quota bars, animation,
filters, and accessibility.  The C ABI/JSON snapshot is versioned; the shell
never parses prompt or provider files itself.

```text
bar/
  Cargo.toml
  crates/cccog-bar-core/
    src/{lib,dispatch,owners,inbox,privacy,usage,graph,quota}.rs
    tests/                 # all synthetic fixtures
  crates/cccog-bar-ffi/   # later Wave 4
  app/CCCOG.Bar.App/      # later Wave 5 WinUI 3 shell
  README.md               # offline boundary and polling/privacy notes
```

Existing .NET callerLabel paths remain the four Batch 1 files plus focused
tests.  No provider command, hop arithmetic, quota enforcement, archive rule,
or existing required field changes.

## 4. TDD waves for Batch 2

Every test is added red first, then made green with the smallest implementation.
All fixtures contain synthetic ids, paths, prompts, token counts, and fake HTTP
responses only; no real credentials, keys, or user data.

### Wave 2 — usage parsing without pricing

1. Codex rollout fixture parses input/output/cache-read/cache-write integers
   from assistant usage and ignores unrelated lines.
2. Claude fixture parses known assistant `message.usage` field variants.
3. Grok fixture parses observed local usage fields and reports unknown when
   usage is absent.
4. Malformed/partial lines are skipped while neighboring valid lines survive;
   diagnostics expose file/offset only.
5. Duplicate message ids and repeated polling snapshots count once.
6. Cursor resumes from byte offset; truncate/rewrite resets safely.
7. Archived provider paths are invisible to usage scans.
8. Large synthetic files prove bounded tail/incremental reads and no full-file
   reread when mtime/length are unchanged.

### Wave 3 — graph reduction and token attribution

9. Labeled dispatch creates the expected source/target nodes, task summary,
   status, job edge id, and token totals.
10. Legacy unlabeled dispatch uses an explicitly ambiguous hop source.
11. PATH A live owner creates an owner edge; stale lease removes it next scan.
12. Requested-to-resolved session updates one edge; duplicate audits dedup.
13. Cyclic hop data remains finite and diagnostic.
14. Direct, child, and PATH A intervals attribute each token sample once;
   queued/failed jobs do not receive unobserved usage; unallocated samples are
   visible once at node level.
15. Snapshot ordering is deterministic and diagnostics/truncation are preserved.

### Quota module tests (same Batch 2, after graph red/green)

16. Codex local `rate_limits` fixture maps each window and latest reset.
17. Claude 200 response maps cards; 401 marks stale/unavailable without leak.
18. Claude 403 inference-only response is unavailable and makes no probe call.
19. Claude expired-token path performs only the approved refresh POST then GET;
   refresh failure is stale and credentials are not written.
20. Grok 200 maps `creditUsagePercent`; missing auth hides the card and makes no
   HTTP call; 401/timeout/malformed responses are stale/unavailable.
21. Percentages are bounded, missing resets stay absent, and provider-specific
   client ids/cards are deterministic.
22. Polling scheduler never runs more often than the configured 60-second
   minimum; injected clock/client makes this deterministic.
23. Request recorder proves no prompt, transcript, cwd, session id, job id, or
   arbitrary local path is sent to any endpoint.

### Later gates retained

Wave 4 will test refresh coalescing, FFI error envelopes, deterministic bounded

## 5. Compatibility, rollout, and rollback

- The bar is additive and read-only.  If quota credentials/endpoints are absent
  or fail, the graph and local token view remain usable.
- CallerLabel remains nullable and old Hosts/workers remain compatible.  The
  worker-first install/reconnect rule from Batch 1 is unchanged.
- Quota polling is opt-in at runtime only in the sense that cards disappear
  when credentials are absent; no provider data is sent to enable them.
- A failed parser, HTTP client, or shell never blocks dispatch.  Keep the last
  valid snapshot and show stale diagnostics.
- Rollback is per commit: remove quota, graph, or usage code independently;
  restore the prior bar core and leave CCCG jobs, owners, inbox, archives,
  provider files, and credentials untouched.

## 6. Risks

| Risk | Mitigation |
| --- | --- |
| Provider usage/quota schema drift | Versioned adapters, synthetic fixtures, bounded diagnostics, stale fallback. |
| Token double counting | Stable message keys, cursor/mtime state, interval attribution tests. |
| Credential exposure | Read-only open, no logging/token persistence, request recorder tests, no local data in requests. |
| Network outage/slow endpoint | Background >=60s polling, timeout, stale badge, never block graph. |
| Inference-only/invalid tokens | Explicit Claude 403 unavailable; no Messages probe. |
| File churn/partial writes | Shared reads, debounce, atomic snapshots, bounded queues. |
| Caller-label spoofing | Display-only label and confidence badge; hop guard remains authoritative. |
| WinUI/FFI packaging | Pure Rust core, separate projects, later x64/ARM64 gates. |

Batch 2 is complete only when the original 140 .NET tests, all new .NET tests,
all Rust usage/graph/quota tests, and every individual project build are green.
